# 초안 3가지 비교·선택

## 사용자 흐름

새 여행 만들기 → 조건 입력 → 최대 3가지 초안을 하나의 DB 초안 문서에 저장 → 기존 초안 검토 화면 → 이동 최소형·최소 방문형·다양한 방문형 버튼으로 전환·편집 → 현재 유형 확정.

초안의 여행 정보 수정 → 최대 3가지 재생성 후보를 묶어 기존 공동 초안에 교체 → 초안 검토 화면에서 유형 전환. 생성 실패 시 기존 DB 초안은 유지한다. 이름만 변경하는 경우 모든 유형을 보존하고 공통 이름만 저장한다.

## 생성 방식

- AI는 기존 생성 작업 한 번만 수행한다. 정상 응답은 1회, 조건 불일치 재시도는 기존처럼 최대 2회다. 선택지마다 AI를 새로 호출하지 않는다.
- AI 방문 추천과 대체 후보를 카카오맵의 실제 업종으로 검증한 뒤 재사용한다. 실패 복구 경로도 검증된 후보 풀을 공유한다.
- 이동 최소형: 기존 AI 일정에 좌표 및 조회 가능한 이동 시간을 반영해 이동 감소를 우선한다. 전역 최단 경로 보장은 아니다.
- 최소 방문형: 하루 일반 방문은 기본 최대 2곳, 선택 스타일 수가 더 많으면 그 수까지 허용하여 가능한 스타일을 보존한다.
- 다양한 방문형: 대체 후보를 우선 사용하며 하루 최대 8곳을 시도한다. 시간 제약 때문에 실제 방문 수가 적을 수 있다.
- 날짜, 숙소·교통 고정 항목, 예산, 추가 요청은 공유한다. 각 초안 안에서는 날짜를 넘어 같은 장소가 반복되지 않게 한다. 서로 다른 초안 사이의 장소 중복은 허용한다.
- 기준 초안에서 반영 가능한 스타일을 잃는 대체 조합은 제공하지 않는다. 후보·시간 부족으로 3개를 만들 수 없으면 중복된 장소 순서의 후보를 제거하고 남은 초안 수를 안내한다.
- 카카오 경로 조회 세션과 호출 한도는 세 선택지가 함께 사용한다. 기본 최대 12회를 3배로 늘리지 않는다. 미확인 구간은 각 후보 안내에 표시한다.
- 일정이 서로 다르더라도 일부 장소가 같을 수 있다. 실제 생성 시간·권한·쿼터는 운영 서버에서 확인해야 한다. 추가 조합 및 검증 시간은 발생한다.

## API

- POST /api/trips/generate-options: GenerateRequest → { options: [{ id, label, description, draft }], warnings }. DB 변경 없음.
- POST /api/drafts: 공통 여행 정보·options(유형별 days/warnings)·selectedOption을 함께 저장. 기존 공동 편집 기능 이용.
- POST /api/drafts/{id}/regenerate-options: 기존 RegenerateDraftRequest → 선택지. 생성 전후 권한·버전 검사, DB 내용 변경 없음.
- POST /api/drafts/{id}/regenerate-selection: { version, draft } → 세 유형을 포함한 공동 초안으로 교체. 기존 권한·낙관적 버전 검사 적용.
- PUT /api/drafts/{id}/option: { version, optionId } → 표시/확정 대상 유형 전환. 기존 유형의 편집 내역과 다른 유형은 보존. 편집 권한·버전 검사 적용.

기존 단일 생성·재생성 API도 유지한다. 유형은 기존 draft_rooms.content JSON 안에 함께 저장되어 앱 재접속 후에도 전환할 수 있다. 기존 types가 없는 단일 초안은 재생성해야 유형 버튼이 생긴다. 편집자는 활성 유형을 공동으로 전환하고 10초 동기화로 공유하며, 보기 전용 참여자는 데이터 변경 없이 원하는 유형을 미리 볼 수 있다. 확정은 현재 활성 유형만 trips에 반영하고 기존 초안 기록의 다른 유형 JSON은 보존한다. 동시에 수정된 초안은 선택 시 덮어쓰지 않고 충돌을 알린다.

## 적용 및 확인

새 JAR를 EC2에 업로드한 뒤 ai-trip-planner 서비스를 재시작한다. 백엔드에 새 API와 조합 로직을 읽히기 위해 필요하다. 앱은 새로고침한다. 새 API가 없는 이전 백엔드로는 선택지 생성이 동작하지 않는다. DB ALTER나 새 API 키는 필요 없다.

테스트는 가짜 AI·지도·경로 응답과 H2를 사용한다. 선택지 차이·7일 날짜·중복 제거·고정 항목 유지·단일 AI 호출·경로 예산 공유·유형별 메모/시각 보존·유형 전환/이름 변경 후 재조회·선택 유형만 확정·권한/동시 수정 충돌을 확인한다. 실제 휴대폰과 유료 API를 사용하는 운영 확인은 별도다.
