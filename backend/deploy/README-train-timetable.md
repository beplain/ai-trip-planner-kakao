# 기차 시간표 자동 도착 시각

기차를 선택하고 여행 첫날 날짜, 카카오맵의 출발 기차역·도착 기차역, 출발 희망 시각을 입력한 뒤 **열차 시간표 조회**를 누릅니다. 희망 시각 10분 전부터의 첫 출발편을 우선 선택하며, 목록에서 다른 열차를 고르면 실제 출발·도착 시각도 바뀝니다. 일정 생성 직전 선택한 편을 다시 조회해 도착 시각을 고정 일정에 반영합니다.

서울역과 수서역, 대구역과 동대구역을 서로 대신 사용하지 않습니다. 지하철역 출구·상점 대신 실제 기차역을 선택해 주세요. 같은 날 도착하는 직통편을 지원하며, 시간표 제공 범위 밖의 날짜나 환승·다음 날 도착은 임의로 계산하지 않습니다. 조회는 예매·운행 확약·좌석 확인이 아닙니다.

## EC2 설정

1. [공공데이터포털 국토교통부 TAGO 열차정보](https://www.data.go.kr/data/15098552/openapi.do)에 로그인하고 활용신청합니다.
2. 승인된 인증키의 **Decoding** 값을 사용합니다. 키는 채팅·GitHub·앱의 `.env.local`에 넣지 않습니다.
3. EC2에서 `sudo nano /etc/ai-trip-planner.env`를 실행해 다음 환경변수를 추가합니다. 아래 설명 대신 실제 Decoding 키를 입력합니다.

```text
TAGO_SERVICE_KEY=여기에_인증키_Decoding_값
```

4. 새 백엔드 JAR를 배포한 다음 `sudo systemctl restart ai-trip-planner`로 재시작합니다. 새 조회 코드와 환경변수는 백엔드 재시작 후 적용됩니다. 기존 배포 순서대로 서비스를 중지하고 JAR를 복사한 후 시작해도 됩니다.
5. 앱을 새로고침하고 가까운 여행 날짜와 실제 기차역으로 조회합니다. 키 오류·조회 불가 시에는 화면에서 **직접 선택**으로 승차권의 시각을 입력할 수 있습니다.

DB ALTER나 앱 패키지 추가 설치는 필요 없습니다. 선택한 열차 정보는 기존 숙소·교통 JSON에 함께 저장됩니다. 카카오 REST 키와 TAGO 키는 서로 다른 서비스의 인증키입니다.

## 공식 명세

공공데이터포털 15098552 페이지의 Swagger(확인일 2026-10-29)를 기준으로 구현했습니다.

- Host: `https://apis.data.go.kr/1613000/TrainInfo`
- `GetCtyCodeList`: 도시 목록
- `GetCtyAcctoTrainSttnList`: 도시별 역명·역 ID (페이지 처리)
- `GetStrtpntAlocFndTrainInfo`: 역 ID·출발일로 조회 (페이지 처리)
- 출발일 `depPlandTime=YYYYMMDD`, 출발/도착 `depplandtime`·`arrplandtime=YYYYMMDDHHmmss`

API 키를 포함한 조회 URL이나 공급자 오류 원문은 화면·로그로 전달하지 않습니다. 역 목록만 12시간 캐시하고 운행 시간표는 생성 시 다시 조회합니다. 자동화 테스트는 모의 공식 응답을 사용하므로, 실제 운영 인증키 설정 뒤의 실시간 조회는 별도로 확인해야 합니다.

## 가는 편·오는 편 조회

- 가는 편은 여행 첫날, 출발 희망 시각 10분 전부터 조회합니다. 08:00 입력 시 07:50부터입니다.
- 오는 편은 귀가 출발역과 귀가 도착역을 지도에서 선택하고 **오는 편 열차 시간표 조회**를 누릅니다. 여행 마지막 날, 희망 시각 10분 전부터 조회합니다. 19:00 입력 시 18:50부터입니다.
- 00:05 입력 시 같은 날 00:00부터 조회하며, 전날 열차를 섞지 않습니다.
- 원하는 열차를 고르면 실제 출발 시각에 맞춰 마지막 날 일정과 탑승 여유 시간을 배치합니다. 원하는 시각 입력값은 그대로 유지합니다.
- 날짜·출발역·도착역·희망 시각이 바뀌면 다시 조회해야 합니다. 귀가 도착역 선택을 해제하면 기존처럼 오는 편 시각을 직접 지정할 수 있습니다.
- 새 필드는 기존 여행 교통 JSON 안에 저장되므로 DB ALTER 없이 새 JAR 배포와 백엔드 재시작, 앱 새로고침으로 적용합니다.
