# 숙소·교통 일정 적용 (2026-10-28)

이번 변경은 앱과 백엔드를 함께 배포해야 합니다. 앱만 새로고침하면 기존 EC2 백엔드는 새 입력 조건을 반영하지 못합니다.

## 기능

- 여행 만들기와 초안의 여행 정보 수정에 자동차/대중교통 선택 추가.
- 카카오맵 숙박(AD5) 검색 결과의 목록·마커에서 숙소 선택. 이름·주소·장소 ID·좌표를 저장하고 체크인/아웃 및 숙소 짐 보관 항목에 연결. 최대 6개 숙소, 입실/퇴실 일차로 여러 날짜에 걸친 숙박과 숙소 변경 지원. 기존 직접 입력한 숙소도 읽을 수 있음.
- 체크인 **예정 시각** 기본 15:00, 체크아웃 기본 11:00. 시는 1시간, 분은 10분 간격의 스크롤로 선택. 실제 숙소 허용 시간은 예약처에서 확인.
- 첫날 도착/마지막 날 출발 장소는 카카오맵에서 선택. 시각은 같은 시·분 스크롤로 선택. 교통편 KTX/비행기/버스/자차 (선택).
- 첫날(2일 이상 여행)은 고정 시간이 허용하면 체크인 뒤에 20:00까지 이어지는 저녁 활동을 포함. 장소 카드는 시작 시각만 표시(예: 19:00). 늦은 도착/체크인으로 배치가 불가능하면 고정 시간을 우선하고 안내.
- 관광·식사 등 추천은 카카오맵에서 확인된 장소만 제공. 확인되지 않은 원래 이름은 일정·경고에 노출하지 않고 대체 후보로 교체. 지도 검색 키/서비스 오류 또는 대체 후보 전부 실패 시 미확인 결과를 반환하지 않고 오류 처리. 실제 영업시간은 별도 확인 필요.
- 짐은 숙소 보관 가능/보관함 이용/직접 소지 중 선택. 기본 직접 소지. 보관함 이용 가능을 자동 확인하지 않음.
- AI에는 이동 방식, 각 숙소와 이용 날짜, 도착/출발 장소, 고정 시각을 전달. 서버가 고정 항목을 직접 추가.
- AI가 숙소 자체·역 자체·체크인/짐 보관/단순 이동을 일반 장소로 반환하면 분리합니다. 일반 추천의 시간이 겹치면 고정 항목 사이의 빈 시간에 재배치하고, 필요하면 AI가 제안한 대체 후보로 매일의 스타일을 보완합니다.
- 고정 항목이 많은 날짜는 일반 장소 1곳까지 허용합니다. 전체 여행 장소 중복·방문 및 이동 여유 검증은 유지합니다. AI가 날짜를 빠뜨리거나 조건을 모두 맞추지 못하면 확인된 카카오 검색 후보로 빠진 일정을 보완합니다. 스타일/저녁 활동을 끝내 채울 수 없으면 부분 초안에 날짜별 안내를 표시합니다.
- 고정 항목을 공동 편집 API로 삭제/시간 수정할 수 없음. 조건 변경은 초안의 여행 정보 수정에서 전체 재생성.
- 기존 여행은 travelDetails가 없으면 기존 동작 유지. 새 조건은 기존 일정을 자동으로 다시 생성하지 않음.

## 시간 검증 범위와 한계

- 일반 장소 방문 60분, 자동차 이동 여유 30분/대중교통 45분을 확보하고 고정 항목과의 충돌 검사.
- 도착 후 준비 시간: 비행기 60분, 그 외 30분. 귀가 전 도착 여유: 비행기 120분, KTX/버스 30분, 자차 15분.
- 시간대는 국내 여행의 한국 현지 시각. 여행 범위 1~7일, 숙소는 여행 안에서 1박 이상.
- 실시간 길찾기·환승·항공편·열차 운행·보관함 재고 조회 기능은 아님. AI에 가까운 장소 묶음을 요청하고, 카카오맵 확인 좌표의 직선거리 합이 줄어들도록 방문 순서를 추가 보정. 숙소·교통 고정 항목 사이에서만 교환하며 식사·야경 시간대를 유지. 실제 도로·대중교통 최단 경로 계산은 아님.
- 카카오맵에서 선택한 숙소·교통편 장소는 해당 좌표와 장소 링크를 고정 항목에 사용. 기존 직접 입력 정보와 위치가 특정되지 않은 보관함 이용은 사용자가 정한 고정 작업으로 구분하며, 확인된 실제 보관함이라고 단정하지 않음. 선택 정보는 기존 travel_details JSON에 저장하므로 추가 ALTER가 필요하지 않음.
- 날짜가 짧거나 조건이 많아 모든 스타일을 매일 충족할 수 없으면 횟수를 제한해 재시도한 뒤 가능한 부분 초안을 반환. 고정 시간과 확인된 장소만 사용한다는 조건은 완화하지 않음. AI 응답 자체를 사용할 수 없으면 지도 검색 기반임을 안내하며 SAMPLE로 구분. 지도 검색이 불가능하고 확인된 장소가 전혀 없으면 오류 반환.
- 일반 장소를 드래그하면 같은 고정 항목 사이에서 기존 시간 슬롯에 배치. 시간 수정은 고정 일정·방문/이동 여유를 지켜야 함.

## EC2 반영 순서

1. PC backend 폴더에서 `./mvnw.cmd clean package` (테스트 포함).
2. SSH Ubuntu에서 `sudo systemctl stop ai-trip-planner`.
3. DB 백업. SSH Ubuntu에서 비밀번호를 프롬프트에 입력:

```bash
mysqldump -u beplain -p --single-transaction --no-tablespaces travel_db > "$HOME/travel-db-before-travel-details.sql"
chmod 600 "$HOME/travel-db-before-travel-details.sql"
```

4. Ubuntu MySQL에 접속해 `2026-10-28-travel-details.sql`의 ALTER 문을 각 한 번 실행. DBeaver AWS 연결에서도 가능.
5. PC PowerShell의 backend 폴더에서 JAR 업로드:

```powershell
scp -i "$env:USERPROFILE\Downloads\ai-trip-planner-key.pem" ".\target\trip-planner-0.1.0.jar" ubuntu@beplain-trip.duckdns.org:/home/ubuntu/ai-trip-planner/app.jar
```

6. SSH Ubuntu에서 실행:

```bash
sudo systemctl start ai-trip-planner
sudo systemctl status ai-trip-planner --no-pager
curl --max-time 10 https://beplain-trip.duckdns.org/actuator/health
```

7. 앱 새로고침 (설치용 앱은 재빌드). 새 여행 또는 초안 재생성으로 테스트.

DDL_AUTO=validate이므로 새 칼럼 없이 새 JAR를 시작하면 검증 오류로 실행되지 않습니다. 데이터는 기존 DB에 유지되고 두 칼럼만 추가합니다. SQL의 ADD COLUMN은 이미 적용됐다면 반복 실행하지 않습니다.

서버/DB 배포와 실제 유료 OpenAI 호출은 로컬 코드 검사에 포함되지 않습니다.

실제 도로·대중교통 이동 시간 연동과 EC2 키 설정은 [README-routing.md](README-routing.md)를 참고하세요.
