# Google 운영시간으로 일정 생성 검증

## 동작
- 새 생성·여행 정보 재생성의 3개 유형 모두에 적용합니다. 기존 초안을 열기만 하면 조회하지 않습니다.
- AI 후보와 카카오 장소 검증을 거친 실제 장소에 대해 Google Places API (New) Text Search로 동일 지점을 찾습니다.
- 이름과 전체 도로명 주소 또는 150m 이내 좌표를 확인합니다. 다른 도로명 주소·다른 지점명·중복 후보는 연결하지 않습니다.
- Google structured periods를 사용합니다. 요일별 시작/종료, 자정을 넘기는 영업, 분리된 영업 구간(휴게시간), 정기휴무, 현재 제공되는 날짜별 특별시간을 검사합니다.
- 현재부터7일 안에 날짜별 정보가 있으면 우선 적용하며, 먼 날짜는 정규 요일 시간을 사용합니다. 그 날짜의 공휴일 특별영업·임시휴무를 확인했다고 단정하지 않습니다.
- 일반 방문은60분입니다. 방문 종료까지 영업해야 통과합니다. 고정 숙소·교통 일정은 변경하지 않습니다.
- 영업하지 않는다고 확인된 경우에만 같은 카테고리의 카카오 확인 대체 후보를 검사합니다. 기존 추가 요청(제외·식사·정확한 개수)을 보존하며, 대체가 없으면 다음 약속 전 범위에서 원래 장소의 시각을 늦출 수 있습니다.
- 이후 실제 이동 시간 보정과 순서 변경 때도 영업시간을 재검사하고, 최종 시각이 유효하지 않으면 제외합니다. 후보가 부족하면 일부 장소가 줄어들거나 생성에 실패할 수 있습니다. 운영시간 정보가 없는 장소는 제외하지 않고 일정에 포함하되, 운영시간 미확인으로 구분합니다.
- 사용자가 나중에 직접 수정한 시간은 자동 재검증하지 않습니다. 생성 시점의 검증입니다.
- Google 원본 hours, place ID, 응답 JSON을 초안/확정 일정 DB에 기록하지 않습니다. 한 번의 생성 요청 안에서만 조회 결과를 공유하고, 생성 완료 뒤 버립니다. 기존 business_hours_json 칼럼은 이번 기능에서 추가로 사용하지 않습니다.
- 카카오 지도와 기존 카카오맵 상세 링크는 유지합니다. 별도 영업시간 화면을 추가하지 않습니다.

## Google 설정
이미 발급한 test 키를 사용할 수 있습니다. Places API (New) 활성화와 결제 계정 연결이 필요합니다.
영업시간 요청은 Text Search Enterprise에 해당합니다. 검색과 재생성은 비용을 발생시킬 수 있습니다.
Google Cloud의 API 제한은 Places API (New)로 지정합니다. EC2 전용 키는 애플리케이션 제한을 IP 주소로 지정하고 EC2의 탄력적 퍼블릭IP를 등록합니다. 172.31.* 같은 사설IP나 휴대폰IP가 아닙니다.
키는 서버 설정에만 등록하며 Expo .env.local/EXPO_PUBLIC 변수나 Git, 채팅에 넣지 않습니다.

## EC2 적용 순서
1. Ubuntu SSH: sudo nano /etc/ai-trip-planner.env
2. 다음 두 줄을 추가/수정하고 저장합니다. 동일한 변수는 한 번만 둡니다.
   GOOGLE_PLACES_API_KEY=구글에서_복사한_키_전체
   GOOGLE_PLACES_MAX_CALLS=100
   nano 저장 Ctrl+O, Enter, 종료 Ctrl+X.
3. PC PowerShell의 backend 폴더:
   scp -i "$env:USERPROFILE\Downloads\ai-trip-planner-key.pem" ".\target\trip-planner-0.1.0.jar" ubuntu@beplain-trip.duckdns.org:/home/ubuntu/ai-trip-planner/app.jar.new
4. Ubuntu SSH:
   sudo systemctl stop ai-trip-planner
   mv /home/ubuntu/ai-trip-planner/app.jar.new /home/ubuntu/ai-trip-planner/app.jar
   sudo systemctl start ai-trip-planner
   sudo systemctl status ai-trip-planner --no-pager -l
   실행 중 JAR에 덮어쓰지 않도록 임시이름으로 업로드하고 종료 후 교체합니다. 새 코드와 환경변수는 프로세스 시작 때 읽으므로 재시작해야 합니다.
5. 확인:
   curl --noproxy '*' --max-time 10 http://127.0.0.1:8080/actuator/health
   sudo journalctl -u ai-trip-planner -n 100 --no-pager | grep 'Google'
   Google 영업시간 설정: 활성 문구를 확인합니다. 키 값은 출력하지 않습니다.
6. Expo에서 r로 화면 코드를 갱신하고, 앱에서 날짜를 지정해 새 초안을 생성합니다.
   sudo journalctl -u ai-trip-planner --since '10 minutes ago' --no-pager | grep 'Google'
   Google 영업시간 검증: API호출=... 확인방문=... 최종제외=... 로그를 확인합니다.

이번 변경에 추가 SQL은 필요하지 않습니다. 관광공사 키는 다른 용도 없이 이 기능에만 사용했다면 더는 필요하지 않습니다. TAGO_SERVICE_KEY(열차)는 유지합니다.

## 제한과 비용
한 생성 요청당 기본 최대100회, 최대4개 병렬, 선택 후보의 사전조회는 최대25초 대기합니다. 세 유형이 같은 매장을 쓰면 요청 내에서 재사용합니다. 사전조회·대체 검색에 공유하는 새 조회 시작 제한은45초이며 이미 전송한 HTTP는 설정된 읽기 타임아웃까지 기다릴 수 있습니다. GOOGLE_PLACES_MAX_CALLS는1~200 범위입니다. 한도·오류·미등록 매장은 미확인 상태로 처리하며, 조회 인증/결제 오류는 생성에 실패하도록 합니다. 정보 미확인 장소는 그대로 포함하고 확인됨 표시를 하지 않습니다.
Google Cloud의 예산 알림은 자동 과금 차단이 아닙니다. API 할당량도 따로 관리합니다.

## 장소별 확인 표시 (2026-11-05)
일반 장소 아래에 생성 당시 운영시간 검증 결과를 작게 표시합니다. 새 초안부터 확인한 날짜·방문시각·검증시점·정규요일/날짜별 기준만 기존 JSON 칼럼에 기록합니다. Google 운영시간 원문과 장소ID는 저장하지 않습니다. 초안과 확정 일정 모두 표시하며, 현재 날짜나 방문 시각이 확인 기록과 다르면 재확인 필요로 표시합니다. 메모만 바꾼 경우는 유지됩니다. 이전에 생성된 일정에는 개별 기록이 없으므로 미확인으로 표시하며, 전체 경고 문구만 보고 과거 장소에 확인 표시를 붙이지 않습니다. 추가 SQL은 없습니다.

## 미확인 장소 유지 및 문구 간소화 (2026-11-05)
운영시간 평가가 CLOSED인 경우에만 대체·시간 조정·제외합니다. 정보 없음, 검색 불일치, 해석 불가 등 UNKNOWN은 원래 일정에 남깁니다. 경로 보정의 시간·순서 적합성 검사와 최종 반환 검사에도 같은 기준을 적용합니다. 원래 여행 기간·숙소·교통 제약에 따른 제외는 유지합니다. 사용자 화면은 '운영시간 확인됨.' 또는 '운영시간 미확인'만 표시하고, 수정된 날짜·시간에는 '운영시간 재확인 필요'를 표시합니다. 검사 기준의 상세 메타데이터는 기록에 유지하되 장소 아래 설명으로 표시하지 않습니다. API 인증·설정 오류는 일반적인 데이터 미등록과 구분하여 여전히 오류로 안내합니다.

## 읍·면 생략 주소와 검색 보완 (2026-11-05)
Google 주소에 읍·면이 생략되더라도 매장명·시도/시군구·도로명·건물번호가 일치하면 동일 지점으로 연결합니다. 양쪽에 읍·면이 명시돼 있는데 다르거나 건물번호가 다르면 연결하지 않습니다. 전체 주소+매장명 검색에서 연결이 안 되면 시도+매장명으로 한 번 더 조회하고 같은 검증 조건을 적용합니다. 재검색은 기존 요청별 총 호출 한도를 공유합니다. Google 지점 연결 로그에서 검색 차수·이름/주소/좌표 일치 수를 확인할 수 있으며 미확인 유지 시 이유를 함께 기록합니다. 키와 응답 원문은 로그에 출력하지 않습니다.


## 매장명 표기와 상세 조회 보완 (2026-11-05)
부산/부산광역시 등 시도 약칭은 같은 주소로 비교합니다. 카페는 한국어 매장명이 같고 도로명·건물번호 및 150m 이내 좌표가 함께 일치할 때 카페 접두·접미어 및 함께 표기된 영문명의 차이를 허용합니다. 이름만 비슷한 다른 지점은 연결하지 않습니다.
검색 결과에서 같은 지점을 찾았지만 운영시간 periods가 없으면 Place Details를 한 번 더 조회합니다. 상세 조회도 기존 요청별 호출·시간 한도를 공유하며 추가 API 호출 비용이 발생할 수 있습니다. 미등록 정보를 확인됨으로 바꾸지는 않습니다. 지점 연결 로그에 앱의 매장명을 추가하고 응답 로그에는 정규/날짜별 기간 개수만 남깁니다.


## 주소가 다른 동일 매장 / 영문명 연결 (2026-11-06)
정규화한 매장명이 정확히 같으면 도로명 주소가 달라도 좌표가 150m 이내인 후보를 연결합니다. 도로명·건물번호가 같고 좌표도 150m 이내이면 Google의 영문 포함 매장명 차이를 허용합니다. 이름으로 확인한 후보를 주소만 일치하는 후보보다 우선하고, 같은 우선순위 후보가 여러 개면 미확인으로 남깁니다. 이름만 같은 먼 지점은 연결하지 않습니다. 이는 서로 다른 매장을 무조건 합치는 규칙이 아니라 주소 표기 및 영문명 차이를 좌표로 보완하는 규칙입니다.
