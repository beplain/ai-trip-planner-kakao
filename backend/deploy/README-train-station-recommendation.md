# 일반 장소의 기차 출발역 추천

가는 편과 오는 편에 같은 기능을 사용하며, 오는 편 시간표는 여행 마지막 날 날짜로 조회합니다. 목적지는 하차할 기차역을 선택합니다.

1. 출발 장소를 선택하면 카카오 로컬 검색으로 반경 제한 없이 KTX 정차역 및 고속철도선 키워드로 각각 검색합니다. 장소 분류가 KTX정차역/고속철도선/고속선인 역만 후보에 넣습니다. 일반 기차역·지하철역·출구·폐역·매장 등은 제외하고 중복을 정리합니다.
2. 두 검색 결과를 합쳐 직선거리 순으로 가까운 고속열차 정차역을 최대 3개 버튼으로 표시합니다. 후보 목록을 가져올 때는 열차 시간표를 조회하지 않습니다.
3. 사용자가 출발역 버튼을 직접 선택합니다. 후보 버튼 옆의 같은 모양인 직접 선택 버튼으로 지도를 열어 다른 역을 고를 수도 있습니다. 직접 선택한 역은 자동 후보 목록에 없어도 유지됩니다.
4. 열차 시간표 조회를 누르면 선택한 역에서 해당 날짜·열차 출발 희망 시각 10분 전부터의 실제 당일 도착 직통열차만 조회합니다. 직통열차가 없는 역도 후보에 포함될 수 있으므로, 이 경우 다른 역을 선택합니다.
5. 출발역을 바꾸면 기존 열차 선택·시간표 목록이 해제됩니다. 원래 출발 장소는 그대로 보관합니다.
6. 후보가 3개 미만이면 확인되는 역만 표시합니다. 모든 역이나 환승열차를 탐색하는 기능은 아닙니다.

출발 장소부터 기차역까지 이동 시간은 계산하지 않습니다. 입력 시각은 열차 출발 희망 시각입니다. 버스·지하철 상세 노선, 첫차·막차, 실시간 배차 조회는 추가하지 않습니다. 일정과 요약에는 선택한 출발역을 열차 출발 지점으로 표시하고 원래 출발 장소는 별도로 안내합니다.

기존 KAKAO_REST_API_KEY (또는 KAKAO_MAP_API_KEY), TAGO_SERVICE_KEY를 사용합니다. 추가 API 서비스 가입·키는 필요하지 않습니다. 교통 JSON에 boardingStation/returnBoardingStation을 저장하므로 DB ALTER는 없습니다.

새 JAR를 EC2에 업로드한 뒤 `sudo systemctl restart ai-trip-planner`를 실행합니다. 서버의 새 추천·재검증 코드를 적용하기 위한 재시작입니다. 앱은 Expo에서 `r`로 새로고침합니다. 테스트는 모의 공급자 데이터로 수행하며 실제 운영 키를 사용하는 조회는 배포 후 확인해야 합니다.

정차역 분류는 카카오 장소 카테고리를 기준으로 합니다. 역 이름에 KTX가 들어가거나 검색에 노출된다는 이유만으로 정차역으로 간주하지 않습니다. 최신 실제 운행은 TAGO 시간표 조회에서 확인합니다. 후보 표시 기준만 바꾸며 시간표 목록의 열차 종류를 별도로 제한하지는 않습니다.
