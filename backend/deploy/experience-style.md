# 체험 스타일 적용

기존 앱은 화면 표시만 체험으로 바꾸고 실제 요청은 액티비티를 전송했습니다. 이제 앱 선택값, 서버 지원 스타일, AI 지시, 검색 후보 구성, 검증 오류를 체험으로 통일합니다. StyleNames는 이전 앱과 저장 초안에서 오는 액티비티를 체험으로 해석하는 호환 처리이므로 유지해야 합니다. 사용자가 직접 쓴 액티비티라는 요청 표현도 계속 인식합니다.

1. 새 JAR와 app/dist를 함께 배포합니다. 백엔드 재시작이 필요합니다.
2. 기존 DB의 실제 저장값까지 변경하려면 DB를 백업하고 백엔드를 잠시 중지한 뒤, DBeaver에서 운영 DB에 연결하여 experience-style.sql을 실행합니다. 완료 후 새 JAR로 시작합니다. DB 자체의 재시작은 필요 없습니다.
3. 웹 배포 후 열려 있는 아이폰 홈 화면 웹앱을 완전히 닫고 다시 엽니다. Expo는 새로고침, APK는 재빌드·설치합니다.

SQL은 이 작업에서 운영 서버에 실행하지 않았습니다. 오래된 로그 파일은 변경하지 않으므로 과거 로그 검색 결과에는 액티비티가 계속 남을 수 있습니다. 스타일 누락 오류는 이제 체험이라고 표시하지만, 실제 체험 장소를 배치하지 못한 일정의 생성 실패 자체를 숨기지는 않습니다.
