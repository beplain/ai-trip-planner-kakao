# DB 초안과 공동 편집

앱 흐름: 일정 생성 → DB에 초안 자동 저장 → 초대/공동 편집 → 이 일정 확정하기 → 내 여행.

## DB 저장 방식

- `draft_rooms`에 초안 JSON(`content`), 참여자 JSON(`participants`), 만든 사람(`owner_id`), 수정 버전(`version`), 수정 시각(`updated_at`)을 보관합니다. `saved_trip_id`가 비어 있으면 편집 중인 초안입니다.
- 초안의 장소 시간·메모·순서·삭제 변경은 `/api/drafts/{id}`의 PUT 요청으로 즉시 DB에 기록합니다. 이름·목적지·기간·예산·스타일·추가 요청 변경은 아래 재생성 API를 이용해야 합니다.
- `draft_invites`는 초대 토큰·초안 ID·권한·만료 시각을 보관합니다. 초대 링크는 7일 후 만료됩니다. 초안 자체는 자동 만료되지 않으며 백엔드 재시작 후에도 유지됩니다.
- 확정 버튼(`/api/drafts/{id}/save`)은 초안 행을 잠그고 버전을 검사한 뒤 기존 `trips`, `trip_days`, `itinerary_places`, `trip_members`에 여행을 만들고 `saved_trip_id`를 설정합니다. 두 처리는 같은 DB 트랜잭션으로 커밋되어 중복 확정을 방지합니다.
- 확정한 뒤에는 여행의 이름·목적지·기간·예산·스타일을 수정할 수 없습니다. 기존 여행 정보 수정 API도 거절합니다. 장소 시간·메모·순서·삭제 기능은 유지합니다. `draft_rooms.content`는 확정 당시 초안 기록이며, 확정 후 최신 내용은 여행 테이블을 조회해야 합니다. 앱에서 확정된 초안 링크를 열면 최신 여행 화면으로 이동합니다.
- 기존 메모리 방식의 초안은 DB에 없으므로 이번 버전 적용을 위한 재시작으로 복원되지 않습니다. 새 버전에서 만든 초안부터 DB에 보관합니다.

## 편집과 동기화

- 초안과 확정 여행 화면 모두 10초마다 최신 변경을 확인합니다.
- `지금 동기화`는 현재 화면을 DB의 최신 내용으로 즉시 갱신합니다. 수정은 별도 요청으로 이미 자동 저장됩니다.
- 장소는 같은 날짜 안에서 0.35초 이상 누른 뒤 위아래로 끌어 놓습니다. 화면 가장자리에서 자동 스크롤합니다. 위/아래 버튼은 제거했습니다.
- 드래그나 메모 편집 중에는 자동 갱신을 잠시 멈춥니다. 수정 버전을 검사하므로 다른 사람의 변경과 충돌하면 최신 내용을 확인하고 다시 수정해야 합니다.
- 초안의 여행 정보 수정 화면에서 재생성을 마치고 돌아오면 즉시 최신 DB 내용을 조회합니다. 늦게 도착한 이전 폴링 응답은 최신 버전 화면을 덮어쓰지 않습니다.
- 지도 보기/일정 공유/동행자 초대는 두 화면에서 동일한 아이콘 버튼 컴포넌트를 사용합니다.

## 적용

### 초안 여행 정보 수정과 AI 재생성

- 초안 화면의 `여행 정보 수정 · AI 다시 생성`에서 이름·목적지·기간·예산·스타일·추가 요청을 변경합니다. 이름만 수정하는 경우도 확인 버튼을 누르면 전체 일정을 다시 생성합니다.
- `POST /api/drafts/{id}/regenerate`는 `{ version, title, input }`을 받습니다. `input`은 최초 일정 생성과 같은 조건입니다. 추가 요청은 초안 JSON의 `request`에 저장합니다. 이전 초안에 저장되지 않았던 추가 요청은 빈 값으로 표시합니다.
- 확인창을 거친 뒤 AI 생성과 장소 검색을 실행합니다. AI 키가 없으면 기존 샘플 모드로 동작합니다. AI 모드에서는 API 사용량이 발생합니다.
- 생성과 장소 검색 중에는 DB 트랜잭션이나 행 잠금을 유지하지 않습니다. 성공 시에만 권한과 버전을 다시 확인하고 초안 전체를 교체합니다. 기존 장소·시간·메모·순서는 새 추천으로 대체되며, 참여자·초대 링크·초안 ID는 유지됩니다.
- 생성 실패 시 기존 초안은 그대로 남습니다. 생성 중 편집·초대 수락·확정 등으로 버전이 바뀌면 충돌을 반환하고 최신 초안을 보존합니다.
- `DraftRegenerationTests`는 실제 AI 요청 없이 성공·실패·충돌·권한·확정 후 수정 차단을 검증합니다.

백엔드를 재시작하면 JPA `ddl-auto=update` 설정에 따라 새 초안 테이블이 생성됩니다. 기존 여행 테이블을 삭제하지 않습니다. Expo에서는 `r`을 눌러 다시 불러오세요. 이미 설치된 Gesture Handler를 사용하므로 추가 패키지 설치는 필요 없습니다. ngrok 주소와 포트가 같으면 ngrok은 계속 켜둬도 됩니다.

## DBeaver 조회 (MySQL)

```sql
SELECT id, JSON_UNQUOTE(JSON_EXTRACT(content, '$.title')) AS title,
       version, saved_trip_id, updated_at
FROM travel_db.draft_rooms
ORDER BY updated_at DESC;

SELECT id, title, budget, version, updated_at
FROM travel_db.trips
ORDER BY updated_at DESC;

SELECT id, trip_day_id, name, visit_time, note, order_index
FROM travel_db.itinerary_places
ORDER BY trip_day_id, order_index;
```

초안은 첫 번째 쿼리, 확정 여행은 두 번째·세 번째 쿼리로 확인하세요. 수정 후 쿼리를 다시 실행해 최신 결과를 확인해야 합니다.

## 검증

`DraftRoomsTests`는 격리된 H2 테스트 DB에서 초안/초대 영속화, 새 서비스 인스턴스에서 복원, 접근 권한, 수정 버전 충돌, 동시 확정 중복 방지, 확정 여행의 이름·예산·날짜·시간·메모 UPDATE, 순서 변경, 장소 DELETE를 실제 SQL 재조회로 확인합니다. 실제 MySQL 데이터와 카카오 계정은 테스트에 사용하지 않습니다. 드래그 정렬 계산은 길이가 다른 카드와 양방향 이동·경계 조건을 별도로 확인했습니다. 실제 휴대폰 터치 확인은 필요합니다.
