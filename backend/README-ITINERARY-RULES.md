# AI 초안 생성 조건

- 여행 기간: 시작일·종료일을 포함해 1~7일. 앱 캘린더와 서버 요청 검증에 동일하게 적용한다.
- 기본 생성은 선택한 스타일 각각을 모든 일차에서 최소 한 장소에 반영하는 것을 목표로 한다. 불가능하면 확인된 후보로 가능한 일정을 반환하고 해당 날짜의 빠진 스타일을 경고에 명시한다. 스타일이 없으면 활동 종류를 제한하지 않는다.
- 매일 선택 스타일을 충족하는 장소를 필수로 포함하며 식사·카페 휴식·주변 관광을 보조 활동으로 추가할 수 있다. 보조 활동이 있다는 이유만으로 전체 초안을 거절하지 않는다. 다만 보조 활동으로 필수 스타일을 대체할 수 없고, 추가 요청의 제외 조건은 프롬프트에 반영한다.
- AI 응답의 `matchedStyles`를 카테고리·방문 시각과 함께 검사한다. 쇼핑은 쇼핑, 맛집은 식당, 자연은 자연, 문화는 문화, 액티비티는 체험, 카페는 카페에 대응한다. 힐링은 자연·카페·관광, 야경은 18시 이후 식당 이외 활동이어야 한다.
- 모든 날짜에 걸쳐 정규화한 장소 이름과 카카오 장소 ID 중복을 검사한다. 장소 대체 시에도 같은 카테고리와 스타일을 유지하고 원래 방문 시각을 사용한다.
- 추천 장소는 카카오 검색으로 확인된 ID·좌표가 있는 곳만 반환한다. 미확인·중복·부적합 후보는 같은 스타일의 대체 후보로 교체하고, 부족하면 지역/숙소 중심의 카카오 카테고리 검색으로 보완한다. 미확인 원래 장소를 경고나 일정으로 노출하지 않는다. 지도 검색 키/서비스를 사용할 수 없을 때 미확인 일정으로 우회하지 않는다.
- AI 응답 검증은 최대 2회, 지도 검색 후 조건 위반에 따른 전체 생성은 최대 2회로 제한한다. 최악의 경우 AI 요청은 총 4회이며 무한 재시도하지 않는다. 이후 복구 단계는 추가 AI 호출 없이 확인된 지도 후보를 사용한다. 검색 요청은 지역/키워드별로 캐시하고 최대 30초 대기한다.
- 복구 단계에서도 고정 시각·방문/이동 여유·중복 금지는 유지한다. 빠진 일차는 실제 검색 결과로 채우며, 배치할 수 없는 날짜는 고정 항목과 안내를 반환한다. 실제 장소를 하나도 확인할 수 없거나 입력한 고정 시간 자체가 모순되면 오류를 반환한다. 최종 오류일 때만 기존 초안을 유지한다.
- 키가 없는 SAMPLE 모드는 고정 시연용 일정으로, 위 AI 스타일 보장의 대상이 아니다.

DB 스키마 변경은 없다. 기존 저장 여행을 자동으로 재생성하지 않는다.

검증: `ItineraryRulesTests`와 `TripGenerationRulesTests`는 실제 유료 API 호출 없이 일별 스타일 누락, 이름/ID 중복, 대체 장소, 기간 제한을 확인한다.


## 카카오맵 실제 업종 검증

AI의 category는 요청 분류이며 확정 근거가 아닙니다. 카카오 검색 응답의 category_group_code, category_group_name, category_name(상세 분류 경로)를 읽어 PlaceCategories에서 허용 업종과 대조합니다. 장소명·검색어에 맛집/쇼핑이 포함되어도 업종 증거로 사용하지 않습니다.

- 식당: FD6/음식점으로 확인된 장소. 카페는 식당에서 제외.
- 카페: CE7/카페 분류가 확인된 장소.
- 쇼핑: MT1/대형마트, 또는 상세 분류의 백화점·쇼핑몰·시장·의류판매 등 허용 쇼핑 업종. 문화시설 영화관은 쇼핑에서 제외. 백화점 안 식당도 쇼핑으로 분류하지 않음.
- 자연·문화·체험·관광도 각 분류에 대응하는 카카오 업종을 확인.
- 모든 업종 정보가 없는 결과, 주거시설·아파트·숙박·부동산·병원·학교 등 부적합 업종은 추천 후보에서 제외.
- 일반 AI 생성, 동일 스타일 대체, 카카오 검색 기반 복구 경로에 동일 기준을 적용. 상위 부적합 검색 결과를 걸러낸 뒤 정상 후보를 선택.
- 기준에 맞는 후보가 부족하면 확인된 후보만으로 부분 초안을 만들고 안내. 분류를 억지로 붙이지 않음.

새 생성·재생성부터 적용됩니다. 저장된 초안/확정 일정은 자동 삭제하거나 재분류하지 않습니다. DB 칼럼 추가는 필요 없습니다. 실제 업종 오류는 카카오 원천 데이터의 분류 정확도에 영향을 받습니다.


## 생성 대기 시간 개선

- AI 응답 검증 재시도는 TripGenerationService에서만 최대 2회 관리. OpenAiItineraryClient 내부에서 다시 두 번 요청하던 중첩 구조를 제거하여 최대 4회가 되지 않도록 함. 정상 응답은 1회만 호출.
- 동일 생성 요청 안에서는 목적지 좌표와 같은 검색어·중심좌표·검색 개수의 카카오 결과를 재사용. 재시도와 대체 생성이 같은 검색을 다시 하지 않음. 사용자 간/영구 캐시는 아님.
- 장소 검색은 병렬 실행하되 전체 검색 단계에 15초의 공통 대기 한도를 적용. 각 검색마다 15초씩 누적 대기하지 않음. 카카오 장소 검색 전용 HTTP 연결 3초/읽기 8초로 OpenAI의 긴 대기 설정과 분리.
- 기존 일정의 독립적인 경로 조회를 서버 공용 최대 4개 작업으로 병렬 실행. 생성 요청당 기존 호출 한도와 총 대기 한도는 유지. 동일 방향 좌표는 중복 호출하지 않음.
- 업종·장소 중복·숙소·교통 시각 검증은 유지. 제한 안에 확인하지 못한 후보/구간을 검증된 것처럼 통과시키지 않음.
- 서버 INFO 로그에 단계=AI/장소검색/경로보정/전체 소요=...ms를 남김. 실제 병목과 개선 폭은 EC2에 새 JAR를 적용한 후 이 로그로 확인. 모델 변경이나 유료 실측 호출 없이 가짜 API로 병렬 실행과 호출 횟수를 검증.
